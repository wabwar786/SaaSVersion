1. Logging in

Open https://<your-app>.up.railway.app/super_admin.html in a browser. This is a separate login from any business — it uses the platform_users table, not users.

Railway variables: if SUPER_ADMIN_EMAIL and SUPER_ADMIN_PASSWORD are still set in the Railway service, remove them. While they exist a deploy can reset the super-admin password.

Password change: Account screen. Lost access and no shell? Set those two Railway variables once, redeploy, then remove them again.

3.1 Modules / features

Shown under the same headings the customer sees — OPERATIONS, INVENTORY & MENU, CUSTOMERS & DELIVERY, FINANCE & REPORTS, SYSTEM (retail gets its own set). Each heading has one switch for the whole group; any single item under it can be switched off on its own.

  • Switch everything on and save = no limit stored.
  • Dashboard sits in Always on and cannot be switched off.
  • A module switched off disappears from the menu and its direct URL is blocked.
  • Day Closing (Stock) is a module like any other — switch it off for a business that does not count stock.
  • The customer sees the change on their next page load — no logout needed.

To see what is switched off for a business, from the console: permissions <slug>.

3.2 FBR / digital invoice

Per business. When on, the POS invoice carries the FBR number and QR. When off, neither appears. It is stored as the fbr module in the same feature list, so it also shows or hides the FBR screen in the menu.

3.3 Licence, renewal and expiry

  • Online business — Renew just extends the expiry date. No key needed.
  • Offline business — generate a key here and give it to the customer; they enter it on the activation screen.
  • After expiry, sign-in is blocked and every page redirects to the activation screen.
  • 30 days after expiry with no renewal, the data is removed.

Two hard rules.
1. --confirm takes the business full name, not the slug. Do not type the < > brackets.
2. A backup taken within the last hour is required before reset or purge (logs and sync are exempt). Run backup <slug> full first.

Sync & offline computers

Deleting on the cloud does not empty the branch computer. After a purge, run resync <slug> transactions --confirm "<name>". That does not touch cloud data — it tells the branch to clear those tables and refill from the cloud on its next sync.

5. Common tasks

Delete a business's old sales

backup mubeen-restaurant full
purge mubeen-restaurant orders --confirm "Mubeen Restaurant"
resync mubeen-restaurant transactions --confirm "Mubeen Restaurant"   offline PC ke liye

Only older than a date: add --before 2026-01-01. Everything transactional instead of just sales: use transactions in place of orders.

Reset a business's admin password

All Businesses → Reset Admin. The old password stops working immediately. If that business also runs offline, the new password reaches the branch on its next sync.

Hide a module from one business

All Businesses → Features → switch the heading or the single item off → Save Modules. Check with permissions <slug>.

Reset a business to empty but keep the login

backup <slug> full
reset <slug> full --confirm "<Business Name>"

Branch computer shows old data that the cloud no longer has

resync <slug> transactions --confirm "<Business Name>"

Branch computer is missing items / categories

repull <slug> all

Nothing is deleted — the branch simply pulls everything again.

Give a customer an offline package

Sign in as that business → System → Download Offline Version (or press F8 on the Sale Point). For a customer who already has it installed, send only UPDATE_PATCH.zip and have them run UPDATE.bat — the offline version does not need downloading again.

6. Stock & menu — what changed in V146

One item form, two screens

The Sale Point's + New Item popup and the left menu's Menu & Categories used to be two different things writing to two different places, so an item made in one never appeared in the other. They are now the same form and the same table. Edit an item anywhere and the Sale Point sells the change.

Three ways stock comes off a sale

SettingWhat happens when the bill closesUse it for
No stockNothing is deducted.Service charge, delivery fee
The same itemThe item that was sold is taken off stock — so many units per sale. Coke tin, water bottle, cigarettes
By recipeEvery ingredient is taken off separately, scaled to the yield and with waste % added on top.Biryani → rice, chicken, masala
Both styles of restaurant are covered. A shop that sells what it stocks uses the same item; a kitchen that cooks from raw material uses by recipe. The same business can mix the two, item by item.

Stock In

Day Closing screen → + Stock In. Item, quantity, rate. That is the whole thing — no purchase order needed for a crate of drinks arriving at the door. Leave the rate blank to keep the current average cost; enter one and the average is re-weighted.

Day Closing (Stock)

Left menu → Day Closing (Stock). For the chosen date, per item:

opening + received - sold - wastage = should be
counted - should be = difference
  • Type the counted quantity only for the items you actually counted. An empty box leaves that item alone.
  • Saving posts one ADJUSTMENT so stock matches the count, and it is written to the Audit Log.
  • Run it again straight after and every difference is zero — that is the check that it worked.
This is the stock closing. Cash closing is still the shift close on the Sale Point. They are separate on purpose: a cashier closes their own shift, stock is counted once for the whole day.

If an item's stock looks wrong

From the console: info <slug> for counts, then on the business itself open Day Closing (Stock) for the date in question — opening, received, sold and wastage are all on one line, so where the number went is visible without a single query.

7. Safety rules

  • never delete <slug> without a fresh backup. It removes the business completely.
  • careful reset full keeps only the admin login. Everything else goes.
  • safe repull, list, info, permissions, audit, query SELECT, footprint, nodes — read-only or non-destructive.
  • Every destructive action is written to the Audit Log with your email and the time.
  • query is read-only and capped at 100 rows — it cannot change anything.
  • Suspending is reversible and touches no data. Prefer it over deleting when a customer has not paid.
